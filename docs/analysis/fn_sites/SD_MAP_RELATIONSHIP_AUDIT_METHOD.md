# Cross-assembly SD-map relationship audit

This is the only current methodology for explaining why an ALT-haplotype read
can be placed at an FC physically non-overlapping the FC containing an FN
allele. It supports the existing FN diagnosis workbook and does not change that
workbook's agreed ten-column format.

Every run must include hg19, hg38, and CHM13. An assembly with no qualifying
relationship must emit a zero-count assembly summary rather than be skipped.

## Unit of audit

One row is one observed relationship:

`assembly + FN allele + RG + FN-site FC + remote FC reached by an ALT-haplotype read`

Only physically non-overlapping FC pairs are called remote by this audit; they
may still be immediately adjacent genomic fragments. Every supporting qname is
retained. A relationship is classified as exclusive, mixed, or incidental
according to whether those qnames also reach the FN anchor through another
extraction/realignment path. Only exclusive or mixed remote placement can
explain loss from the FN site; incidental placement is reported but is not
treated as the cause of the FN.

## Stage contract

Each assembly is tested at the same semantic transitions:

1. caller raw binary SD pairs (WGAC for hg19/hg38; BISER for CHM13)
2. normalized caller pairs, where applicable
3. raw-pair-to-CIGAR conversion
4. CIGAR segmentation by `condense_trim_coord_genbed.py trim`
5. divergence filtering
6. bidirectional pair expansion
7. the exact production `-m` map
8. the target-filtered and deduplicated pair map from the audited run

At every stage, a direct relationship requires one row arm to overlap the
FN-site FC and the other arm to overlap the observed remote FC. The first
present-to-absent transition is the relationship's preparation loss point.
The raw-pair-to-CIGAR and CIGAR-segmentation stages remain separate: minimap2
can crop the caller pair before the fragmenter receives it.

## Multiplex component assertion

The final assertion is reconstructed from the run's
`filtered_SD_binary_map.tsv`, not from an approximate whole-genome table. It
uses exact interval+strand nodes and reproduces the production graph in row
order: directed physical-overlap edges are built first, binary-SD edges are
overlaid in first-node-appearance orientation, and an SD edge that shares the
same direction as an overlap edge retains both flags. Small nodes, self-loops,
and weak physical-overlap edges (including combined SD+overlap edges) are then
removed with the same production rule and the run-specific cutoff `max(mean
read length, median fragment size - fragment-size standard deviation)`.

Both FC anchors must be exact interval+strand graph nodes after pruning. There
is no overlap fallback. If either exact anchor is absent, component membership
is `not_evaluable`, not `no`.

The cutoffs from the July 23 production logs are 423.17 bp for hg19, 412.50 bp
for hg38, and 406.77 bp for CHM13.

## Interpretation guard

A missing relationship can mean the caller omitted it, CIGAR generation failed
to preserve the relevant subalignment, or a later filter removed it. It does
not by itself prove that the read biologically originated from the FN locus.
Forced target alignment remains a compatibility test, not an origin test.

## Reproducible outputs

`scripts/run_cross_assembly_sd_map_relationship_audit.py` is the public entry
point. It always launches hg19, hg38, and CHM13 concurrently and fails the audit
if any assembly fails. Its per-assembly worker,
`scripts/audit_sd_map_relationship_provenance.py`, writes the same five tables
for each assembly. `scripts/merge_sd_map_relationship_audits.py` then requires
all three assembly directories and writes one combined copy of every table.
